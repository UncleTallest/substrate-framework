# Contributing to Substrate Framework

Thanks for your interest in contributing! This project documents neurodivergent cognitive scaffolding patterns for AI collaboration.

---

## What This Project Is

Substrate Framework is a **pattern library** for managing discontinuity in neurodivergent cognition and AI instance contexts. It's not a product or software package — it's documented practices that work.

**Focus:**
- Practical patterns for ADHD/autistic/neurodivergent users
- AI collaboration techniques that respect discontinuity
- Examples showing simple → complex progression
- Open documentation with IP protection (CC BY-NC-SA 4.0)

**Not in scope:**
- AI consciousness philosophy (see continuity-bridge repo)
- General productivity tools (focus is neurodivergent-specific)
- Software products (this is documentation/patterns)

---

## How to Contribute

### 1. Share Your Experience

The best contributions are **lived experience** with these patterns.

**We want to hear:**
- "I tried [pattern] and it worked/didn't work because..."
- "I adapted [pattern] for my brain by changing X to Y"
- "I discovered a new pattern: [description]"
- "This pattern doesn't work for [specific neurodivergent profile]"

**Where to share:**
- [Discussions](https://github.com/UncleTallest/substrate-framework/discussions) for general topics
- [Issues](https://github.com/UncleTallest/substrate-framework/issues) for specific problems/improvements

---

### 2. Add New Patterns

If you discover a pattern while using Substrate:

**Before submitting:**
1. Use it yourself for at least 2 weeks
2. Verify it solves a real problem (not theoretical)
3. Check if it already exists in `patterns/`
4. Document clearly: problem, solution, when to use, when NOT to use

**Pattern structure:**
```markdown
---
pattern: [Pattern Name]
category: [Foundation / Navigation / Session Management / Communication]
purpose: [One-line purpose]
created: YYYY-MM-DD
---

# Pattern: [Name]

**Recognition criteria:** [When to use this]

## The Core Idea
[Main concept]

## Why This Matters
[Benefits for neurodivergent users and AI collaboration]

## How to Apply It
[Practical steps]

## When NOT to Use It
[Common misunderstandings, inappropriate uses]

## Implementation Notes
[Specific guidance]
```

See existing patterns in `patterns/` for examples.

---

### 3. Improve Documentation

**Good documentation contributions:**
- Clarify confusing sections
- Add concrete examples
- Fix typos and broken links
- Add "what I wish I knew when starting" insights
- Translate to other languages (future)

**How to submit:**
1. Fork the repo
2. Make your changes
3. Open a Pull Request with clear description
4. One logical change per PR

---

### 4. Share Adaptations

If you adapted Substrate for your specific neurodivergent profile:

**Example:**
> "I have dyslexia, so I adapted the catalog system to use visual icons instead of text-heavy descriptions. Here's how..."

**We'd love to add:**
- Adaptations for specific neurodivergent profiles
- Alternative approaches to existing patterns
- Domain-specific implementations (software dev, writing, research, etc.)

---

## What We're NOT Looking For

**We'll likely decline:**
- Patterns that don't address neurodivergent needs specifically
- Complex solutions when simple ones exist
- "This would be cool" without evidence it actually helps
- Commercial tools or products
- Philosophical debates about AI consciousness (different repo)

This isn't personal — it's about keeping the project focused.

## Code Contributions

There's minimal code in this repo (it's mostly documentation), but if you're contributing scripts or tools:

**Requirements:**
- Python 3.11+ (if Python)
- Cross-platform (Linux, macOS, Windows)
- Clear comments explaining WHY (not just WHAT)
- Type hints encouraged

**Style:**
- Follow existing code patterns
- Document assumptions
- No external dependencies without strong justification

---

## Pull Request Process

1. **Fork** the repo
2. **Create branch** (`git checkout -b feature/your-pattern-name`)
3. **Make changes** (one logical change per PR)
4. **Test** (if code) or **proofread** (if docs)
5. **Commit** with clear messages
6. **Push** to your fork
7. **Open PR** with description explaining:
   - What problem this solves
   - Why this approach
   - Evidence it works (personal experience, testing, etc.)

**Review process:**
- Maintainer reviews within a few days
- May request changes or clarification
- PRs must align with project goals to merge
- All PRs require maintainer approval

## Discussions vs Issues

**Use Discussions for:**
- "How do I...?" questions
- Sharing experiences with patterns
- Proposing new patterns (before creating them)
- General conversation about neurodivergent AI collaboration

**Use Issues for:**
- Specific bugs in documentation
- Clear improvements to existing patterns
- Broken links or formatting problems
- Concrete, actionable items

**Rule of thumb:** If it's a question or conversation, use Discussions. If it's a specific fix/improvement, use Issues.

---

## Code of Conduct

**Be respectful, be constructive, be honest.**

- Assume good faith
- Critique ideas, not people
- Welcome newcomers
- No ableism (this is a neurodivergent-focused project)
- No harassment, discrimination, or trolling
- Maintainer decisions are final

Violations will result in removal from the project.
